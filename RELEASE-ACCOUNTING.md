# Бухгалтерия

Активирован раздел в основном меню. Фильтры: заказчик, объект, услуга, период. Таблица из актуальных рейсов в работе и выполненных; выбор отдельных строк или всех. Запланированные/отменённые исключаются. Цены содержат НДС22, округление каждой строки до копейки.

Создание счёта за услуги, счёта на аванс без рейсов, УПД и реестра. Черновик сохраняет услуги; при формировании фиксируются реквизиты исполнителя и покупателя. Для выставления нужны название/ИНН/адрес, для счетов — банк, БИК, счёт. Нумерация реестров отдельная для объекта и года; отменённые номера не используются повторно. Рейс нельзя повторно включить в тот же вид документа, включая черновики и параллельные вкладки.

Документы имеют статусы черновик/сформирован/отправлен/подписан/отменён. Отправка и подписание отмечаются вручную, это не интеграция с ЭДО и не электронная подпись. Счёт не завершает рейсы. Подтверждённое формирование УПД/реестра завершает рейсы, начисляет зарплату существующим триггером и показывает документ во второй строке рейса. Подтверждение водительских накладных и талонов остаётся отдельным. Выставленные документы запрещают незаметное изменение и удаление связанных рейсов.

Оплаты — накопленная сумма на сегодня с историей изменения, не банковская выписка. Зачёт доступного оплаченного аванса ограничен заказчиком, объектом, услугами и остатком счета; выручка и денежное поступление не дублируются. Счета автоматически появляются в календаре платежей; фильтр объекта/услуги показывает долю до копейки. Факт прибыли продолжает рассчитываться по рейсам и расходам.

Доступна загрузка HTML печатной формы, печать/сохранение PDF средствами браузера, CSV реестра для Excel/Google Sheets. Пока шаблоны организации не предоставлены, УПД — базовая форма для проверки; на ней и в интерфейсе это обозначено. Утверждённый шаблон УПД, XML для ЭДО, автоматическая отправка и подпись не подключены. Добавление шаблона на Drive не активирует подстановку автоматически. Сформированные документы прикрепляются логически через неизменяемый снимок в базе, а не через публичный URL; их можно скачать из рейса. Автоэкспорт этих форм в архив водительских файлов отдельно не заявлен.

Проверки: unit-тесты финансов, SQL authenticated с ROLLBACK (НДС, версии, повторное выставление, защита рейсов, завершение/начисление/связи, отдельные счётчики, зачёт и оплаты, календарь, другой владелец и запрет прямых записей). Playwright desktop1440/mobile390: фильтры, выбор, счёт/аванс, оплаты/зачёт, PDF/CSV, завершение УПД, документы рейса, отсутствие JS ошибок и горизонтального переполнения страницы. Браузерные сценарии используют контролируемые RPC-данные; реальные правила базы проверяются отдельно SQL. Статус Render и проверки рабочего URL фиксируются в RELEASE-STATUS.json.

Security advisors: новые предупреждения о SECURITY DEFINER относятся к намеренно открытым authenticated RPC записи; auth.uid/owner и доступность ссылок проверяются внутри, anon/PUBLIC EXECUTE отозван. Прямые INSERT/UPDATE таблиц запрещены. Старые уведомления общих таблиц другой CRM не изменялись.

Восстановление: исходники, npm ci, миграции прошлых версий, затем database/accounting.sql → accounting_calendar.sql → accounting_guards.sql. Проверить журнал миграций перед применением; не повторять уже выполненные DDL. npm test, npm run build, публикация respectlogistic/customers в srv-dbci9j1srm7s73b5ejvg. Секреты задаются в окружении; архив не содержит пользовательских записей, токенов и .env. Он не заменяет backup БД.
