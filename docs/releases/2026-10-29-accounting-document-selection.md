# Бухгалтерия: рабочие документы и групповое удаление

Причина старых строк: удаление рейса не уничтожает бухгалтерский черновик; read_accounting сохраняет все документы для аудита. Рабочий список раньше проверял только deleted_at документа. Четыре сохранённых черновика без действующих исходных рейсов потому оставались видимыми в CRM, хотя Google Drive уже исключал их.

Теперь рабочий список использует общую с Google Drive проверку действующих источников: удалённые/отменённые документы, документы без исходных рейсов, со смешанным устаревшим составом или без действующего родительского счёта скрываются. Архив открывается явным флажком; причины исключения подписаны в строке и карточке. Номера, снимки, оплаты и история сохранены. Формирование устаревшего черновика и создание новых закрывающих к недействующему счёту не предлагаются. Самостоятельные авансы остаются видимыми. Расчёт задолженности и финансовые записи не переписываются.

Добавлены флажки выбора документов, выбор всех документов текущей выборки и «Удалить выбранные документы». Применяется существующий защищённый RPC: УПД/реестр перед счётом; оплаченные/подписанные/с зачтённым авансом документы архивируются. Каждая операция проверяет владельца и версию; при частичной ошибке успехи сохраняются, ошибки названы, необработанные документы остаются выделенными. Подтверждение позволяет отменить операцию. Уже удалённые/архивные записи истории повторно не выбираются. Если выбран только счёт с действующими невыбранными закрывающими, сервер сохраняет запрет удаления и объясняет причину.

Проверки: npm test, production build/TypeScript, браузерные сценарии бухгалтерии на компьютере и телефоне, включая старые/смешанные источники, архив, выбор всех, отказ в подтверждении, частичный сбой и повтор, порядок связанных документов и сохранение оплаченного подписанного аванса. Production RPC удаления четырёх устаревших черновиков проверен транзакционно с ROLLBACK. Постоянных изменений клиентских данных проверка не выполняла. Схема/RPC не меняются, SQL-миграция не нужна.

Восстановление: распаковать архив точного commit, npm ci, восстановить секреты отдельно в Render, npm test и npm run build, развернуть на существующем сервисе.
