# Водитель: заявки → смена → повторяющиеся рейсы

Заявки открываются нажатием, упорядочены по дате и времени. Адреса, точки и контакты можно выделять и копировать; есть общая кнопка копирования. Ссылки Яндекс Карт используются напрямую, координаты строят автомобильный маршрут в порядке широта/долгота. Android допускает официальные домены Яндекса и ya.ru.

Отдельная вкладка «Смена»: выбор госномера из закреплённых/принятых назначенных машин, актуальный пробег, крупная кнопка старта и переход в рейсы. Машина активной смены сохраняется в доступном списке. На принятой заявке можно выполнить несколько рейсов: «В пути на погрузку» → «Погрузка» → «Выгрузился» → документы и ручной объём из талона → «Сохранить рейс». Сервер сохраняет прогресс между открытиями приложения, проверяет порядок этапов, водителя, назначение, версию заявки и открытую смену. Завершение вызывает существующий dispatch_result/crm_save_trip; отдельного финансового реестра нет. Повторы с тем же объёмом не дублируют рейс/зарплату, изменение сохранённого объёма отклоняется.

Документы проходят предпросмотр, поворот, проверку разрешения и локальное OCR rus+eng. Worker, WASM и языки поставляются с приложением, внешний OCR-сервис не используется. Уверенность OCR и количество распознанных символов выявляют явно плохие снимки. Это эвристика, а не доказательство полноты каждого поля/корректной ориентации; водитель подтверждает края, поля и направление текста. Окончательная проверка комплекта остаётся у диспетчера. Документы копируются в существующие файлы смены с реальным trip_id, доступны в CRM и существующем экспорте Google Drive. Их подтверждение не происходит автоматически.

Окончание смены требует конечного пробега и комментария о состоянии машины. Поломка прерывает незавершённый рейс, сохраняя историю и фото. Обычное завершение блокируется до сохранения текущего рейса. Оба сценария ведут в зарплату. Календарь показывает начисления за выбранную дату, базу, премию и оформленные удержания из существующего payroll. Налог компании не уменьшает зарплату.

Заправка: фото чека, литры, цена и итог с проверкой арифметики. Сервис: описание, фото ремонтируемого узла, чек и сумма. Фото открываются для просмотра. В CRM «Сервис и водители» добавлены «Заправки и ремонт» и технический комментарий/причина окончания периода управления. Эти записи представляют отчёт водителя; они не создают автоматическую бухгалтерскую проводку или вторую зарплатную запись. При прерванной загрузке незавершённая запись видна с отсутствующим чеком; повтор формы с теми же значениями продолжает загрузку без дубля.

## Установка и восстановление

Ветка публикации respectlogistic/customers; Render srv-dbci9j1srm7s73b5ejvg, Supabase yoqejkedmksmvbqagqru. Миграция `20261025161617_driver_mobile_workflow.sql` добавляет отдельные таблицы прогресса, водительских расходов и фото; RLS включён, прямые записи запрещены. RPC намеренно доступен anon с проверяемой непрозрачной сессией водителя и authenticated для чтения владельцем. Полномочия владельца проверяются через auth.uid(); ключи владельца не передаются водителю. Предупреждения advisor о SECURITY DEFINER документируют эту существующую модель; прямой доступ anon к таблицам закрыт.

Миграция применена к рабочей базе. При восстановлении не применять её повторно, сначала сверить migration history. Архив исходников не содержит клиентскую БД, секреты, ключи подписи, .env или node_modules. Сборка npm ci && npm run build; npm start -- --hostname 0.0.0.0. Существующие секреты Render сохраняются. Откат интерфейса не требует удаления новых таблиц, фото или рейсов.

## Проверки

- npm test и TypeScript, production build.
- PostgreSQL 16: существующие сценарии распределения и новые driver-mobile.integration.sql.
- Рабочий Supabase: новая интеграция с ROLLBACK, настоящим crm_save_trip и проверкой ровно одного payroll-начисления; тестовые данные не оставлены.
- Browser desktop/mobile: назначенная машина без постоянного закрепления, открытие заявки и ссылка карты, начало смены, восстановление прогресса после reload, последовательные этапы, реальный локальный OCR синтетического документа, ручной объём, зарплата/календарь, чек заправки.
- Проверка на физическом Android-устройстве и на реальных бумажных талонах не выполнена; качество OCR зависит от камеры и бланка.

Точный commit, результаты финального CI, статус Render и ссылки артефактов фиксируются в RELEASE-STATUS.md архива после завершения публикации.
