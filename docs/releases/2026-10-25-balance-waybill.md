# Остаток компании и сведения для накладной

В обзоре вместо заглушки добавлен ручной денежный остаток на дату: «Указать остаток» → сумма в рублях → дата → сохранить. Это остаток всей компании, он не зависит от фильтров заказчика/объекта/услуги/периода и не пересчитывается автоматически. Выручка/прибыль/расходы остаются существующими расчётами по операциям. Расходы вносятся в «Прибыль → Учесть расход», оплата выставленных счетов — в «Бухгалтерия → Оплата счёта»; выручка — по выполненным рейсам. Ручной остаток не создаёт ни доход, ни расход, ни вторую оплату. Сумма хранится в копейках, допускает ноль и отрицательные значения; дата не позднее текущей по Москве. Проверка версии предотвращает перезапись параллельного изменения.

В «Создать/редактировать заявку» поле часового пояса заменено на точку выгрузки. В новых заявках часовой пояс по умолчанию Москва; при редактировании прежний сохранённый часовой пояс остаётся. «Кому» заполняется из краткого названия заказчика (name), полное используется только при отсутствии краткого. После получателя отдельными строками идут «Наименование», «Масса», затем «Комментарий». Новые поля необязательные; масса — текстовое сведение для накладной, не фактически перевезённые т/м³. Реальная выгрузка и начисления сохраняются прежним отдельным действием. Новые поля сохраняются на сервере и в неизменяемых снимках документов, видны водителю. Маршрут выгрузки использует точку, если заполнена, иначе адрес.

## Миграции и восстановление

Две версии уже применены к существующей схеме yoqejkedmksmvbqagqru:
- 20261025131431_dispatch_waybill_fields.sql — новая версия save_dispatch с явными полями payload.
- 20261025131432_company_balance_snapshot.sql — отдельная таблица ручного остатка с RLS и проверенными RPC чтения/сохранения. anon не имеет доступа; чтение изолировано по владельцу, прямое изменение запрещено.

При восстановлении применять только отсутствующие версии по порядку, не запускать первоначальную dispatch-схему повторно. Предыдущие клиенты совместимы с добавленными полями. Откат интерфейса не требует удаления таблицы остатка и сохранённых данных. Исходники собираются npm ci && npm run build, запускаются npm start -- --hostname 0.0.0.0, прежнее окружение Render; ветка respectlogistic/customers. Точный commit и статус публикации в архивном RELEASE-STATUS.md. Архив содержит исходники и SQL, не клиентскую БД и не секреты.

## Проверки

Production build/TypeScript, npm test. Шесть browser-сценариев desktop/mobile: новые поля, краткое имя при различном полном имени, необязательная масса, прокрутка нижних полей, сохранение/продление/печать; ввод остатка с десятичной запятой и сохранение фильтров/расчётов обзора. SQL на PostgreSQL16 и рабочей схеме с ROLLBACK: новые поля действительно сохраняются, фактический учёт остаётся отдельным; точность копеек, ноль/отрицательный остаток, запрет лишних десятичных знаков/будущей даты, конфликт версии, прямой записи, чужого владельца и anon. Тестовые записи не сохранены. Browser auth/API ответы синтетические, пользовательские production-сессии не использовались.

Проверка Supabase advisors: новых предупреждений об anon-доступе или отсутствующей RLS нет. Lint 0029 отмечает намеренно доступный authenticated SECURITY DEFINER RPC сохранения остатка: прямое изменение таблицы запрещено, auth.uid обязателен, owner_id не принимается от клиента, версия и сумма проверяются. Изоляция проверена настоящими ролями authenticated/anon. Справка: https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable .
