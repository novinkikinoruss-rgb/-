# DaData: поиск заказчиков и автозаполнение

Добавлен поиск юридических лиц по названию или ИНН в карточке заказчика. Из списка до пяти организаций пользователь выбирает нужную; заполняются краткое/полное наименование, ИНН, КПП, ОГРН, юридический адрес и руководитель. Контактные и банковские поля сохраняются. Автосохранения нет: реквизиты проверяются перед сохранением карточки. Поиск по точному ИНН сохранён. ИП пока не поддерживаются: действующая модель CRM принимает ИНН юридического лица из 10 цифр.

Запросы идут через сервер /api/company с проверкой сессии Supabase. DADATA_API_KEY хранится только в серверном окружении Render. Используются suggest/party и findById/party. Обработаны отсутствие ключа, отсутствие результатов, таймаут и лимиты провайдера. Ручной ввод доступен при сбоях. При изменении поискового запроса старый запрос отменяется; устаревший ответ по ИНН не заменяет отредактированные реквизиты.

Активация: Render → respectlogistic → Environment → DADATA_API_KEY, значение API-ключа из личного кабинета DaData. Secret key для подсказок не требуется. Не использовать NEXT_PUBLIC_ для этого ключа. После сохранения окружения выполнить публикацию и проверить реальный поиск в авторизованной сессии. Ключ пользователем ещё не подтверждён; проверка реального провайдера не выполнена.

Миграции SQL не требуются; изменения схемы, RLS и данных отсутствуют. Бело-зелёный дизайн карточки сохранён.

Проверки: npm test, npm run build; tests/company-lookup.test.mjs проверяет авторизацию, соответствие ИНН, исключение ключа из ответа и ошибки сервиса. Браузерные тесты company-search и customers проверяют выбор, заполнение/сохранение полей, ошибки и мобильную вёрстку на фикстурах. Точный результат финальных проверок и commit записаны в сопровождающем журнале выпуска.

Восстановление: распаковать архив исходников, npm ci, настроить серверное окружение, npm run build. Не содержит .env, ключи, node_modules или клиентские записи.
