# Восстановление доступа к CRM

Причина неработающей ссылки: Auth URL Configuration проекта Supabase сохраняет localhost:3000 как адрес возврата. В CRM также отсутствовала форма нового пароля. Приостановленный проект Supabase возобновлён; проверены ACTIVE_HEALTHY, Auth health через сайт HTTP 200 и read-only SELECT 1. Пароль владельца оператором не менялся.

Добавлена /reset-password и ссылка «Забыли пароль?» на форме входа. Страница отправляет письмо через штатный Supabase Auth, поддерживает прямой PASSWORD_RECOVERY возврат и ручную вставку оригинальной ссылки из письма, включая обёртку Gmail. Она извлекает recovery token локально и проверяет через verifyOtp; по вставленному URL не выполняет переходов или запросов. Принимает только HTTPS origin текущего Supabase проекта, путь /auth/v1/verify и type=recovery. Чужие ссылки и истёкшие токены не разрешают смену пароля. Требуются подтверждение нового пароля и минимум 12 символов. После сохранения запрашивается выход из сессий; JWT до истечения срока может сохранять действительность. URL-фрагмент очищается при recovery, Referrer-Policy no-referrer задан для страницы.

Важно: настройка Site URL/Redirect URLs в панели Supabase не изменялась этим выпуском. Для прямого перехода из письма владельцу проекта нужно в Supabase Auth → URL Configuration установить Site URL https://respectlogistic.onrender.com и добавить Redirect URL https://respectlogistic.onrender.com/reset-password. До этого восстановление работает через ручную вставку ссылки из последнего неоткрытого письма в форму на /reset-password. Не передавать эти ссылки в чат, журналы или архив.

CI: браузерные задания закреплены на Ubuntu 24.04, совместимой с Playwright 1.56.1; ubuntu-latest перешёл на неподдерживаемую этой версией Ubuntu 26.04.

Проверки: npm test, production build/TypeScript; browser fixtures desktop/mobile для прямого возврата, обёрнутой Gmail ссылки с localhost, несовпадающих паролей, сохранения, выхода, чужого домена и истёкшего токена. Реальные пароли и ссылки владельца в тестах не используются. Работа почтового ящика и смена пароля самим владельцем требуют его действия. SQL-схема и бизнес-данные не изменены, миграции не нужны.
