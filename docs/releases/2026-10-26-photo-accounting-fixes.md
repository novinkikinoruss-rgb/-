# HEIC, оформление рейса и документы к счёту

Водительский файл HEIC на снимке экрана не декодировался стандартным браузерным createImageBitmap. Добавлено локальное преобразование HEIC/HEIF через libheif-js 1.23.5. Декодирование, масштабирование, JPEG-сжатие и настоящий OCR работают в отдельном Worker. Прогресс, отмена, повтор и общий предел 45 секунд завершают зависшую обработку и освобождают Worker с дочерним OCR. Поддерживаются JPEG/PNG/WebP и HEIC; ни оригинал, ни OCR-текст не уходят внешнему OCR-провайдеру. Неподходящий файл или превышение времени дают русское сообщение. Невозможно гарантировать чтение любого редкого HEIF-кодека; окончательно поля и ориентацию проверяет водитель, комплект — диспетчер.

Тайм-аут запроса к водительскому API увеличен с 25 до 90 секунд (фото — 120), серверный запрос к Supabase ограничен 40/60 секундами. Ошибки сети и тайм-ауты, включая чтение тела ответа, показываются по-русски. Во время записи виден статус. Выбранное фото остаётся на экране после ошибки. Повтор одной загрузки использует тот же UUID; выбор другого фото создаёт новый UUID. Реальный сервер уже поддерживает идемпотентность фото, так что потерянный ответ не создаёт дубль при повторе.

Заявка: таблица реквизитов, отдельные карточки погрузки и выгрузки, контакты и примечания. Сохранены выделение и копирование текста. Рейс: номер №З-1 и объект сверху, оформленная шкала этапов и кнопки «Сломался»/«Завершить смену». Эти кнопки сразу открывают соответствующий вариант окончания смены с обязательным комментарием. Удалён запрошенный поясняющий текст из зарплаты.

Бухгалтерская ошибка подтверждена на рабочей базе: current_date=2026-10-25 (UTC), но московская дата уже 2026-10-26. Дата документа сравнивается с московской датой, дефолт даты документа и начальный период бухгалтерии используют ту же зону. Ошибки неправильной даты, вида документа и превышения 500 рейсов разделены. Предел 500 сохранён; выборку больше лимита нужно разделить.

После применения фильтра автоматически выбраны подходящие рейсы (до 500); внизу таблицы показаны выделенный объём отдельно по т/м³, число рейсов, сумма и кнопка создания счёта. В карточке счёта можно создать УПД и реестр. Сервер проверяет владельца, заказчика, исходный счёт, принадлежность рейсов и совпадение количества/цены/единицы/услуги/объекта со снимком счёта. УПД включает весь счёт, реестр — все его рейсы выбранного объекта. При нескольких объектах выбирается объект реестра. Связь invoice_id хранится в БД; номер исходного счёта сохраняется в снимке для печати. Повтор не может перепривязать документ. Чужой счёт/чужие рейсы недоступны. Счёт с активными дочерними документами сначала требует отменить эти документы. Прежние счета и несвязанные закрывающие документы не перепривязываются автоматически.

Создание черновика УПД/реестра не завершает рейсы; формирование по-прежнему требует подтверждения. Выставление счёта не завершает рейсы. Подтверждение комплекта водителя остаётся отдельным. Расчёт НДС22, единственный payroll, нумерация, история и блокировка финансовых снимков сохранены. Шаблон произвольного УПД/ЭДО не добавлялся.

## Проверки и восстановление

Проверены TypeScript, unit-тесты, production build, 20 auth browser сценариев, сценарий HEIC → реальный OCR → потерянный ответ загрузки → повтор с прежним UUID → единственный документ, desktop/mobile. Отдельные бухгалтерские browser сценарии проверяют объём, счёт/аванс/оплату/зачёт/CSV и связанные УПД/реестр. API в браузерных тестах синтетические; настоящая БД проверена SQL с ROLLBACK.

На PostgreSQL16 проверены миграции и интеграции распределения, водителя, новой связи документов. На рабочем Supabase прошли accounting-invoice-links.integration.sql (включая московскую полночь) и прежняя accounting.integration.sql с НДС, payroll, блокировками, нумерацией и RLS. Тестовые данные откатаны. Физическое устройство пользователя и исходный HEIC со снимка экрана недоступны; использован настоящий HEIC с синтетическим документом.

Миграция 20261025220950_accounting_invoice_links_moscow_dates.sql уже применена к yoqejkedmksmvbqagqru. При восстановлении сверить migration history и не применять повторно. Новая связь nullable, старые документы сохранены. Откат интерфейса не требует удаления новых связей/снимков. Секреты и постоянную Android-подпись не менять. Сборка npm ci && npm run build, запуск npm start -- --hostname 0.0.0.0.

Точный commit, CI, Render Live и опубликованные проверки записаны в RELEASE-STATUS.md архива. Архив содержит исходники и синтетические проверки, не является копией клиентской БД.
