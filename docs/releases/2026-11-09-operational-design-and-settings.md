# Операционный интерфейс и настройки вида в базе

Изменяется прежняя CRM respectlogistic, ветка respectlogistic/customers. Новая CRM, другие приложения и логины не затрагиваются. Оформление обновлено по фотографии пользователя: тёмно-синяя верхняя панель, горизонтальные разделы, светлая рабочая область и белые панели с небольшим скруглением. У меню есть прокрутка для доступа ко всем разделам на узком компьютере; на телефоне — раскрывающееся меню. Фильтры рейсов и заявок расположены справа на большом экране и над списком на телефоне. Финансовые правила, связи заявок/рейсов/документов, зарплаты и подтверждения документов сохранены.

Таблицы получили более читаемый текст, контрастные закреплённые заголовки, выделение строк, независимую прокрутку и настраиваемую плотность. В рейсах остаются закреплёнными выбор и номер, сохранены изменение ширины, порядок столбцов, сворачивание документов и страницы по 25/50/100 строк. Длинный текст можно переносить полностью либо просматривать одной строкой с подсказкой. Общая плотность и перенос действуют на таблицы остальных разделов. Перестановка видимых столбцов доступна мышью, а всех столбцов — стрелками в панели «Столбцы».

## Сохранение настроек

По прямому требованию пользователя настройки вида хранятся в БД, а не в браузере. Добавлены public.respectlogistic_user_settings (PK owner_id + setting_key), read/save RPC SECURITY INVOKER, owner-only RLS и ограничение размера JSON. Анонимный вызов запрещён. Клиент передаёт ожидаемый owner только как дополнительную проверку; сервер сопоставляет его с auth.uid(), право доступа не определяется значением клиента.

Ключ tables содержит плотность, перенос и вид заказчиков (карточки/список/канбан). Ключ trips содержит порядок, ширины и количество строк на странице. Действующий браузерный кеш столбцов больше не читается и не обновляется. Сессия входа Supabase хранится своим обычным способом и не является настройкой таблиц. В режиме демонстрации без базы изменения вида временные и не выдаются за сохранённые в БД.

Записи отправляются с задержкой 600 мс и последовательно, чтобы движение границы столбца не создавало запрос на каждое событие. При выходе/смене пользователя очередь и запросы отменяются; серверная проверка p_owner защищает от запоздавшей записи под другой сессией. В чистом браузере и при возврате к вкладке перечитываются настройки БД. При отказе чтения элементы настроек блокируются до повтора: браузерный кеш или значения по умолчанию не записываются поверх сохранённого вида. При отказе записи видна ошибка, несохранённое изменение остаётся для явного повтора. Между двумя устройствами действует последний успешно сохранённый вариант одного ключа; одновременное редактирование разных параметров одного ключа не является системой совместного редактирования.

## Миграция и проверки

Миграция 20261109181151_user_table_preferences.sql уже применена к yoqejkedmksmvbqagqru. SQL-файл первоначально создан Supabase CLI 2.81.3; имя согласовано с фактической версией в migration history. Не выполнять повторно на существующей схеме. Клиентский прокси разрешает только два новых RPC, прямой доступ к произвольным таблицам не добавлен. Предупреждения security advisors до/после не увеличились.

tests/ui-settings.integration.sql проверяет сохранение разных ключей, обновление, размер/тип значения, отказ анонимному пользователю, подмену владельца и RLS. Проверка рабочей базы выполнена в транзакции с ROLLBACK; после отката отдельный запрос подтвердил отсутствие тестовых записей настроек. Производственные финансовые записи не изменялись. В CI эта же проверка запускается после миграций на отдельной PostgreSQL фикстуре.

Browser fixtures проверяют 300 рейсов, страницы по 100 строк, плотность, закрепление заголовков/номера при горизонтальной и вертикальной прокрутке, отсутствие переполнения на телефоне, сохранение ширины/порядка/числа строк и вида заказчиков в чистом браузере, изоляцию другого пользователя, отказ записи с успешным повтором и отказ чтения без браузерного fallback. Скриншоты содержат только синтетические записи. Полный набор авторизации/бухгалтерии/распределения/водителей и демонстрационный интерфейс проверяются отдельно; точные результаты и commit — в статусе выпуска на Диске. Реальная сквозная сессия владельца в браузере не используется.

## Восстановление

Распаковать архив точного commit, npm ci, восстановить существующие секреты Render отдельно, сверить migration history, применить только отсутствующую миграцию, npm test, npm run build, развернуть ветку respectlogistic/customers на существующем сервисе. Откат интерфейса на 11aa95ad452a0a0610b4235ef90f3e78f629475b не требует удаления новой таблицы настроек; сохранить её для истории. Источники и синтетические проверки не включают .env, токены, node_modules, пароли, клиентские записи или резервную копию БД.
