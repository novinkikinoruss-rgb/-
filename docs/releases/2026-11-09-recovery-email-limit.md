# Лимит отправки писем восстановления

Пользователь получил общее сообщение об ошибке отправки кода. Auth logs подтвердили HTTP 429, error_code over_email_send_rate_limit, error "email rate limit exceeded" (2026-11-09T14:10:09Z). Встроенная почта Supabase отправила письма recovery в 13:30:48Z и 13:39:49Z; последующие запросы ограничены. Приложение и база доступны. Повторные реальные запросы для диагностики не отправлялись.

Текущая документация https://supabase.com/docs/guides/auth/rate-limits подтверждает общий лимит встроенного провайдера 2 письма/час на проект и отдельное 60-секундное ограничение recover на пользователя. Точное время снятия ограничения провайдером не подтверждено. Лимит встроенной почты нельзя снять изменением интерфейса. Для регулярной доставки требуется Custom SMTP или Send Email hook с настроенным провайдером; SMTP и тариф без данных владельца не менялись.

CRM теперь отдельно показывает часовой лимит писем, ограничение числа запросов и ошибку соединения. Отказ не отмечается как успешная отправка, поле кода не появляется до принятого запроса. Проверка desktop/mobile использует синтетический 429 с настоящей формой ошибки провайдера. Схема БД, пользователи, пароли и финансовые данные не менялись, миграции не нужны. Шаблон с {{ .Token }} остаётся отдельной настройкой Supabase, его сохранение владельцем требуется подтвердить.

Восстановление: исходники точного commit, npm ci, существующие настройки Render отдельно, npm test, npm run build; публикация ветки respectlogistic/customers.
