# Trip form, short numbers, status changes and document upload

The equipment list used optgroup headings as if they were choices. These headings cannot be selected in native mobile or desktop selects. The form now has two native radio controls for company or contractor equipment. Contractor selection precedes vehicle/driver selection. Changing source or contractor clears incompatible assignments. Empty fleets show where to add a vehicle. Archived equipment remains available only when retaining the current trip assignment.

New trip numbers are integers from 1 through 1000. An empty field allocates the first unused number inside an owner/application advisory lock. Numbers belong to this app, persist across dates, and are not reused after deletion. Existing trip numbers remain unchanged. Manual duplicates and values outside the range are rejected. Once all 1000 are reserved, creation reports that the range is exhausted; extension requires a deliberate numbering policy change.

The trip table now includes a status selector with the Completed option. It uses the existing transactional save operation and optimistic version. Invoice/payment locks and employee payroll requirements stay in force. Completing a trip with no confirmed document set leaves a document warning.

Document upload no longer traverses the generic 12-second Supabase proxy and browser storage SDK. The browser sends multipart content to /api/trip-files with a 120-second upload timeout. The application verifies the user, owner/app-scoped trip and file size, transfers bytes to the private bucket with a 60-second upstream timeout, then registers the document. All formats are accepted, including Office files, archives, HEIC and files with no MIME type or extension. Original bytes/names are preserved; storage uses application/octet-stream and attachment downloads. The 10 MB per-file limit remains. Registration failure attempts cleanup of newly uploaded orphan content. No privileged database key is used. Repeated registered upload IDs are idempotent. The original Failed to fetch could not be reproduced in a real browser from this restricted environment; the release removes the short-timeout transfer route and adds controlled server handling instead of claiming a proven single network cause.
