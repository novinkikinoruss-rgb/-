# Google Диск: отдельные папки рейсов и исключение удалённых документов

Проблема: общий каталог машины смешивал файлы разных рейсов за день. Независимая выгрузка бухгалтерии включала сохранённые черновики, даже когда все их исходные рейсы были удалены. Два таких черновика от 26 октября попали на Диск из бухгалтерской истории.

Изменения:
- Путь рейса: CRM документы / заказчик / объект / услуга / дата / госномер / Рейс №<номер>.
- Номер для очереди читается сервером из защищённого rl_crm_trips; ID клиента не определяет название или права доступа к чужим рейсам.
- Конечная папка привязана к ID рейса через приватную appProperty. Папка с тем же названием и файлами другого рейса не используется. Подготовленную пустую папку или папку, содержащую только собственные файлы этого рейса, сервер проверяет и привязывает к рейсу.
- Собственные файлы из старой общей папки машины перемещаются по проверенным меткам файла/рейса и родителю. Повторная загрузка оригиналов не требуется.
- Один фильтр определяет состав бухгалтерских файлов и строк реестра: исключаются cancelled, deleted_at, документы без действующих связей и документы хотя бы с одним удалённым/отменённым исходным рейсом или устаревшим снимком. Авансы без рейсов сохраняются. Дочерние УПД/реестры с исключённым счётом также не выгружаются.
- Удалённые рейсы и исключённые документы дают положительный список ID для очистки: только файлы, ранее созданные CRM, с точными appProperties и проверенной принадлежностью к корню CRM документы, перемещаются в корзину Google Drive. Соседние ручные файлы и файлы вне корня не затрагиваются. Отсутствие записи в неполном списке файлов не считается удалением. Финансовая история в базе сохраняется.
- Ошибка Google Sheets API выводится с точной причиной; недоступность реестра не блокирует обновление действующих файлов на Google Диске. Неполная синхронизация не помечается успешной. Сохранённая ошибка теперь также видна после повторного открытия раздела.

Проверки: npm test, TypeScript/production build; тесты отдельного каталога, переноса без копирования, повторной синхронизации, отказа от чужой одноимённой папки, границ корня, ручных файлов, пагинации очистки, архивных/отменённых/осиротевших/смешанных документов и реального состава запроса реестра. Браузерная проверка формы и документов на компьютере и телефоне. Сгенерированный сервером пакет запросов Sheets успешно применён к реестру через подключённый Google Drive; в текущем списке закрывающих оставлены действующие документы.

Схема Supabase не изменялась. Не требуется миграция. Восстановление: исходники конкретного commit, npm ci, переменные Supabase через защищённые настройки Render, npm run build; публикуемая ветка respectlogistic/customers. Google OAuth-подключение владельца сохраняется в Supabase Vault. Исходный архив исключает .env, токены, зависимости и записи клиентской базы. Источник не является резервной копией базы или бизнес-документов.
