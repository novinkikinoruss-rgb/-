# Кабинет водителя 0.1

CRM: меню «Сервис и водители». Личный кабинет: `/driver`. Доступ создаётся для активного водителя собственного автопарка. Машина должна быть закреплена за ним в «ТС и водители». Передайте временный пароль лично; при первом входе требуется новый пароль. Пароли доступа хешируются bcrypt; отдельные случайные сеансы водителя не дают JWT владельца CRM.

В выпуск входят:

- Договорные сервисы: адрес, телефон, график, часовой пояс, срок договора и виды работ.
- Заявка водителя → согласованная диспетчером запись → прибытие → подтверждение выполненных работ. ТО и масло используют действующий журнал обслуживания и интервалы машины.
- Индивидуальные заметки из CRM. Текст и доступы зашифрованы с ключом Vault, раскрываются по нажатию, не сохраняются открытыми в localStorage.
- Начало и конец периода управления фиксируются сервером. Сегодняшний отчёт также завершает его открытый период, если этот период начался до создания отчёта. Отправка исторического отчёта не завершает более новую смену.
- Отчёт: пробег, технические замечания, снабжение, комментарий, до 6 JPEG по 2 МБ после сжатия. Для отправки нужно фото одометра. Только принятие диспетчером обновляет пробег автопарка. Снабжение: нужно / в работе / выдано.
- Постановления: время, машина, место, причина, сумма и номер. Автоматическое назначение по интервалу `[начало, конец)`; без истории водитель не выдумывается. Ручное назначение требует основания. Водитель может ознакомиться или возразить.
- «Передать в учёт зарплаты» создаёт связанную запись в существующем журнале штрафов один раз. Само удержание выполняется обычной процедурой в «ТС и водители». В кабинете показывается сумма фактических удержаний.
- Фото, привязанные к рейсу за эту дату/машину/водителя, появляются во второй строке рейса. Комплект документов подтверждается отдельно. Выгрузка учитывает оба хранилища; для реальной отправки на Google Диск всё ещё требуется OAuth-подключение самого приложения.

Фотографии этого модуля хранятся закрыто в БД; выдаются только проверенному владельцу или соответствующему водителю. Общие лимиты 6 × 2 МБ ограничивают размер отчёта. Оригинальные документы любых форматов по-прежнему загружаются через существующий раздел рейсов (10 МБ на файл).

## Развёртывание и восстановление

Исходники: GitHub `novinkikinoruss-rgb/-`, ветка `respectlogistic/customers`. Render `srv-dbci9j1srm7s73b5ejvg`. БД `yoqejkedmksmvbqagqru`. Существующие данные другой CRM не переносить.

На базе с предыдущими миграциями выполнить по порядку:

1. `database/driver_service.sql`
2. `database/driver_notes_shifts.sql`
3. `database/driver_duties_fines.sql`
4. `database/driver_trip_bridge.sql`
5. `database/driver_release_hardening.sql`

Это миграции однократного применения. При восстановлении существующей базы использовать журнал Supabase migrations, не выполнять CREATE TABLE повторно. Vault-ключ заметок и данные пользователей не входят в исходный архив; для восстановления зашифрованных заметок из резервной копии БД нужен соответствующий ключ из защищённой резервной копии Vault.

Проверки: `npm test`, `npm run lint`, `npm run build`; `tests/driver-service.integration.sql` в транзакции с ROLLBACK; браузерные `tests/e2e/driver.spec.mjs` и `tests/auth/service.spec.mjs`. Браузерные сценарии с фикстурами проверяют интерфейс; они не являются записью в реальную учётную запись клиента. На production отдельно проверять SHA `/api/health`, загрузку `/driver` и отказ неавторизованных запросов.

## Android и границы выпуска

Java-клиент в `android/`, сборка `.github/workflows/android-driver.yml`. При наличии четырёх signing secrets получается подписанный APK, при отсутствии — только неподписанный артефакт для проверки сборки. Инструкция ключа: `android/README.md`. GitHub-интеграция текущего сеанса возвращает 403 при обращении к Actions secrets, поэтому ключ через неё не настроен. Ключ не создавался и не публиковался в репозитории.

Требуется интернет. Чат, распознавание чеков, полный процесс назначения и выполнения рейсов, push при закрытом приложении и офлайн-синхронизация остаются следующими модулями. Сборка не заменяет проверку камеры, установки и обновления на физическом Android.
