# CRM: заявки, история смен, документы и Google

Дата: 28 октября 2026. База до изменения: 080e66f53cedb453d657575fd86d7caf96afd3e9.

## Поведение

- Из входа водителя доступен отдельный вход администратора в распределение; используются обычные права владельца CRM. Удаление/отмена заявки сохраняет бухгалтерский аудит, но скрывает отменённые назначения и их историю у водителя. Удалённые рейсы и их файлы недоступны водителю, включая ранее сохранённые ID файлов.
- Номера заявок выводятся без дефиса; старый формат ввода при копировании поддерживается. В списке распределения показаны машины, водители и статусы: оранжевый до подтверждения, зелёный после принятия.
- История и документы на экране рейсов водителя относятся к текущей смене. Закрытие смены или отмена назначения прерывает незавершённую работу.
- Таблица рейсов компактнее. Вложения разделены на документы рейса, накладные/фото водителя и закрывающие формы с номерами. Нативные окна рейса и компании прокручивают отдельный div вокруг fieldset, действия остаются доступны.
- Черновики бухгалтерских документов позволяют менять дату, срок и примечание; неоплаченные сформированные документы исправляются новой версией. Удаление отменяет документ и скрывает его, сохраняя номер/историю. Подписанные и оплаченные документы архивируются с сохранением финансового учёта. Активные дочерние документы и зачёты продолжают защищать исходный счёт. Архив не исключает долги из расчёта.
- Сообщение о реквизитах уточняет отсутствующие данные. Банковские реквизиты должен заполнить владелец; проверка не обходится.
- Созданы «CRM документы» и «CRM реестр» (ссылки в GOOGLE-SETUP.md). Начальный реестр содержит текущие данные владельца; архив исходников не содержит эти записи.
- В разделе «Рейсы» — защищённая форма OAuth и пошаговое подключение. Секреты владельца шифруются через ключ Supabase Vault; анонимный доступ и прямое чтение шифротекста закрыты. OAuth использует случайное состояние, S256 PKCE и Secure/HttpOnly cookie. Учётная запись Google подключается владельцем в обычном браузере.
- После авторизации Google: исходные файлы и HTML-формы документов отправляются в Drive; три листа зеркалируют рейсы, закрывающие и вложения с номерами, статусами, значками и ссылками. Отдельный архив бухгалтерских форм включает авансы и документы по удалённым рейсам. Запись строк RAW исключает интерпретацию пользовательского текста как формул.

## Ограничения и настройка

OAuth-клиента у владельца пока нет: создание клиента и Google consent остаются обязательными пользовательскими действиями. До этого сервер Google не подключён. Инструкция: docs/GOOGLE-SETUP.md и непосредственно CRM. В External / Testing разрешение обычно истекает через 7 дней; Production и требования проверки Google описаны в инструкции.

Автосинхронизация раз в минуту действует, пока открыт раздел «Рейсы», также есть ручная кнопка. Фоновое задание при закрытой CRM не создавалось. Изменения вносятся в CRM, реестр является зеркалом. Существующие архивные файлы на Drive не удаляются автоматически при удалении рейса; история скрывается в приложении водителя. Базовая HTML-форма УПД не является настроенным шаблоном компании или XML для ЭДО.

## Проверки

- npm test: доменные, прокси, загрузка файлов, бухгалтерия, водитель; новые OAuth/state/PKCE/cookie/refresh/callback и Google API проверки с контролируемым транспортом.
- Production Next build / TypeScript.
- 22 браузерных сценария авторизованного интерфейса на компьютере и телефоне. После исправления прокрутки дополнительно 4 целевых сценария: реальное колесо до нижних полей в компании и рейсе, форма OAuth, скачивание оригиналов, создание связанных документов.
- Чистый PostgreSQL 16: bootstrap, все миграции, распределение, мобильный процесс, бухгалтерские связи/редактирование/архив/удаление/исправленные версии, баланс компании.
- В рабочей Supabase проверены транзакциями с ROLLBACK: удалённая история и фото, изоляция водителей, бухгалтерские документы/версии/связи, Google Vault/секреты/права владельца и анонимного пользователя. Тестовые данные не сохранялись.
- Supabase advisors просмотрены. Новые SECURITY DEFINER RPC намеренно предоставлены authenticated и проверяют auth.uid/владельца; прямое чтение секретов запрещено и проверено.
- Реальный OAuth обмен с Google невозможен до создания владельцем OAuth-клиента; тесты используют фиктивные реквизиты.

## Восстановление

Исходники: распаковать архив конкретного commit, npm ci, установить серверные переменные Supabase через защищённые настройки Render, npm run build. Ветка публикации respectlogistic/customers, сервис srv-dbci9j1srm7s73b5ejvg. Новая миграция 20261028164142_lifecycle_documents_sync.sql применена к yoqejkedmksmvbqagqru. Не запускать повторно вручную и не удалять финансовую историю при откате приложения. Для новой базы нужны штатные database/*.sql и вся история миграций; tests/dispatch-bootstrap.sql — только тестовая схема. Источник архива не является резервной копией клиентской базы. Google-подключение настраивается отдельно, ключи/токены в архив не включены.
